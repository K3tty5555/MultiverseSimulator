按照 LifePlanner 六人专家团审视流程执行。

## 流程

1. **确定审视范围**：根据 $ARGUMENTS 或待审视内容判断涉及的层：
   - 前端信号：component, Vue, CSS, 样式, 交互, 页面, 动画, D3
   - 后端信号：API, Flask, SQLite, LLM, 数据库, 接口
   - 视觉信号：颜色, 字体, 间距, Token, 图片, 素材, 设计
   - 产品信号：功能, 用户, 流程, 入口, 体验

2. **选择 Agent 组合**（用户可通过参数直接指定，如 `/lp-review 视觉+前端`）：

   | 范围 | Agent 组合 |
   |------|-----------|
   | 全栈功能 | 全部 6 个 |
   | 页面视觉 | 视觉设计 + 交互设计 + 前端 |
   | 纯前端逻辑 | 交互设计 + 前端 |
   | 后端 API | 架构 + 后端 |
   | 新功能评审 | 产品 + 交互设计 |
   | 设计方案 | 产品 + 交互设计 + 视觉设计 |
   | 安全/性能审计 | 架构 + 后端 + 前端 |

3. **读取 Agent 定义**：从项目根目录 `.claude/agents/` 读取所需 Agent 的 `.md` 文件。

4. **准备审视内容**：
   - 用户指定了文件/目录 → 读取对应内容
   - 在 Plan Mode 中 → 读取当前计划
   - 否则 → 读取最近代码变更（`git diff`）

5. **并行派发**：用 Agent 工具在一条消息中并行发出所有选中的 Agent。每个 Agent 收到其专属 prompt（将 `{document_content}` 替换为实际审视内容）。

6. **汇总输出**：
   - 去重：多个 Agent 指出相同问题的，合并为一条，标注来源
   - 按严重度排序：严重 > 重要 > 建议
   - 格式：

   ```
   ## 六人专家团审视结果

   范围：{检测到的范围}
   参与审视：{Agent 列表}

   ### 严重问题
   - **[来源] 问题标题**：描述。建议：...

   ### 重要问题
   - ...

   ### 建议
   - ...

   ---
   共发现 N 个问题。需要修订哪些？
   ```

7. **后续处理**：等用户选择修订哪些，按指示修改。修订后不自动重新审视，除非用户要求。
